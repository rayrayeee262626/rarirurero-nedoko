# 下書きとバックアップ

## 下書きの扱い

このリポジトリは公開。Pages CMSの「公開する」をOFFにしても、本文・画像・過去の履歴はGitHub上から読める。サイトで非表示にする機能と、秘密に保管する機能は別。

- 未公開のまま保管したい原稿は、非公開のメモや別のprivateリポジトリに置く。
- この公開リポジトリへ保存するのは、GitHubでも公開してよい内容だけにする。
- 患者・個人の情報、秘密鍵、DB exportを保存しない。
- 誤って秘密を書いた場合は、記事を非表示にするだけでは解決しない。秘密鍵なら失効・再発行を優先し、内容に応じて履歴や複製への対処を検討する。

今回、リポジトリの公開設定やCMS設定・既存記事は変更していない。非公開下書きの自動公開フローは未実装。privateリポジトリへそのまま切り替えると現在のブラウザ取得が動かなくなるため、別途設計する。

## ソースと記事のバックアップ

変更をコミットした状態で、次を実行する。

```sh
npm run backup:source
```

`backups/` にGit bundleとSHA-256を作り、Gitで検証する。コミット済みのローカル履歴・取得済みrefsを対象とし、取得していないリモートブランチ、未コミットのファイル、ignoredファイルは含まない。全リモート履歴が必要なら、先に承認した読み取り経路でfetchする。出力はGit管理・公開用distから除外される。

bundleとチェックサムは、作業環境とは別のアクセス制限された保存先にもコピーする。同じ環境のbackupsだけでは、環境消失への備えにならない。

復元は元リポジトリを上書きせず、別ディレクトリへ行う。

```sh
git bundle verify /path/to/source.bundle
git clone --branch codex/improve-home-discovery /path/to/source.bundle restored-site
```

ブランチ名は保存時に含まれる対象ブランチへ置き換える。復元後は `npm run check` と `npm test` を実行する。復元や検証で本番デプロイはしない。

## D1・Cloudflare・FC2は別のバックアップが必要

ソースのbundleには掲示板投稿、Cloudflare設定・秘密値、FC2カウントは入らない。

本番反映前に、管理画面の読み取りでDB名・DB binding・プラン・復旧可能期間を確認する。その後、承認された手順でD1のschema/data exportを取り、公開Gitには置かず、暗号化した別の保存先に保管する。別DBに復元して確認し、本番DBの上書きはしない。Time Travelは期間制限があるため独立バックアップを併用する。

CloudflareのデプロイID、配信設定、変数名、binding対応を記録し、秘密値は秘密管理へ保存する。FC2は管理サービス側の復元可否を確認する。今回、実D1のexport・復元・削除やCloudflare設定変更は行っておらず、DBバックアップ完了とは扱わない。
