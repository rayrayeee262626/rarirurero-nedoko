# 掲示板バックアップの状態

2026-11-13 UTC 更新。**掲示板アプリケーションの全データ・スキーマの暗号化バックアップに成功**。

投稿2件・返信1件に加え、非公開列・採番情報・実際のスキーマを保存し、ローカル復元と暗号化の往復を検証した。GitHubの保管は90日。詳細・復号鍵の注意・未完了の定期化は [Cloudflare運用記録](cloudflare-operations.md) を参照。

以下は接続設定前に作成した、公開投稿だけの救済コピーについての記録。完全な掲示板バックアップとは別物。

## 実施したこと

- 公開掲示板APIをGETのみで読み、取得可能な親投稿2件・返信1件を救済用JSONに保存した。
- 投稿本文をログ・文書・公開GitHubへ出していない。保管先は公開ソースの外側で、作成時のumaskは077。
- SHA-256を作成し、SQLiteのメモリ内に別名の復元用テーブルを作って、本文・日時・ID・返信先の一致と整合性を確認した。
- 本番への投稿・削除、D1変更、Cloudflare設定変更、デプロイはしていない。

これは公開表示データの救済用コピー。D1全体の完全性を保証しない。ip_hash・DBスキーマ・他テーブル・Cloudflare設定は含まない。取得中の変更もあり得るため、ある一時点の厳密なスナップショットではない。現行APIはページ全体の返信を200件に制限しており、上限に達した場合は不足の可能性を警告する。

## 再取得と検証

Python 3、curlが必要。GET以外の本番操作を行わない。

```sh
python tools/backup-bbs-public.py save --directory /path/outside/source/private-backups
python tools/backup-bbs-public.py verify /path/to/snapshot.json
python -m unittest discover -s tests -p 'test_bbs_backup.py'
```

save先はリポジトリの外側に限定。取得途中のエラーを成功扱いにしない。公開JSONに余分な列が現れても許可した公開列だけを保存する。verifyはネットワークを使わず、元ファイルや実DBを書き換えない。作業環境消失に備え、生成したsnapshot.json・snapshot.sha256・README.txtを別のアクセス制限された保存先にもコピーする。

この形式は本番bbs_postsへそのままimportできるSQLではない。欠落したip_hash等を適当に補って本番へ書き戻さない。復旧の際は、実D1スキーマ・既存投稿との重複・欠落列の方針を確認して別途計画する。

## 接続設定前の未完了事項（履歴）

今回の環境にはCloudflareの認証済み接続がなく、利用可能なCloudflareプラグインも検索で見つからなかった。そのため次は管理画面の確認が必要。

1. 対象PagesプロジェクトのDB bindingを確認し、本当に使っているD1を特定する。
2. 契約プランとTime Travelの復旧可能期間を確認する。
3. D1のschema/dataをSQL exportし、公開Gitに入れず保護された場所に保存する。秘密値をチャットへ貼らない。
4. チェックサム・取得日時・対象DB・件数を記録する。本文やIPハッシュは報告に掲載しない。
5. 別のローカルDBまたは隔離したテストD1へ復元し、親子関係・件数・本文・索引を確認する。本番DBは上書きしない。
6. 独立した保存先と定期取得・保存期間を決め、定期バックアップを設定して初回の成功を確認する。

その後、管理画面で過去7日以内のTime Travel機能を確認し、SQL exportの代わりに単一SELECTでのアプリケーションDB全体のバックアップが完了した。定期取得・長期の独立保管先はまだ未設定。公開APIの救済コピー自体を、それらの完了として扱わない。
