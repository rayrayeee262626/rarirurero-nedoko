### 所有者による最小限の手続き

1. Cloudflare Analytics Engineの初回有効化は2026-11-14に所有者が実施済み。プレビューbindingのHTTP 204を確認し、以後の接続・本番公開はアシスタントが行う。初回手続きを繰り返す必要はない。
2. Search Consoleの https://search.google.com/search-console/sitemaps?resource_id=https%3A%2F%2Fprint-pon.pages.dev%2F で既存プロパティを選び、https://print-pon.pages.dev/sitemap.xml を送信する。すでに成功なら再送不要。プロパティがなければURLプレフィックスで同URLを追加し、既設HTMLタグで所有権確認する。既存タグを削除・差し替えない。

Google側では「ページのインデックス登録」を送信済みサイトマップで絞り込み、登録・未登録理由を確認する。個別確認の優先ページは九九と小1足し算。「URL検査」で公開URLテストとGoogleが選んだcanonicalを確認し、未登録なら登録をリクエストする。サイトマップ送信とインデックス登録は別の状態。通常の教材サイトにGoogle Indexing APIを使ったり、廃止されたサイトマップpingを送って登録済み扱いにしたりしない。

既存の接続ではGoogle Search Consoleの管理API権限がなく、使えるGoogleログインセッションも提供されていない。連携候補も調査したが、サイトマップ送信・URL検査を完了できる接続は確認できなかった。トークンやGoogleパスワードをチャットへ貼らない。

### 数字をアシスタントが継続取得する場合

既存CloudflareトークンでPagesの読取・公開は可能だが、Web Analyticsのサイト一覧とAnalytics Engine SQLはHTTP 403（Authentication error）。集計を自動取得するには、所有者が既存トークンへAccount Analytics Readを追加する必要がある。Web Analyticsサイトの設定をAPIで点検する場合はAccount Settings Readも必要。変更はCloudflareのトークン設定で行い、値を再発行・チャット送信しない。今回、権限を勝手に拡張していない。

## 施策を続ける判断

- Web Analytics：Visits/PV、参照元、着地ページを同じ7日間で比較する。LINEなどは直接流入に含まれることがあるため、流入元だけで厳密に効果を断定しない。
- X・note：それぞれの表示数やリンククリックが確認できる場合は、サイト側の数字と合わせて見る。
- 操作集計の有効化後：単元別のgenerate/pdf/printを比較する。自動初期生成はカウントしない。保存・印刷開始の操作数であり、成功した人数や完了率ではない。
- 継続利用：匿名イベントから同じ人の再訪率は出せない。初期協力者の任意の感想と、単元ごとの操作数の推移を別々に扱う。

閲覧が増えた単元では、見本・説明が期待と合っているかを先に確認する。保存や印刷で困る人がいれば、その問題を優先する。反応が小さいうちは、広告費や新機能・ページの追加を増やさない。
